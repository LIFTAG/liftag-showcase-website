# Website localization

## Architecture

Nuxt i18n owns the active EN/SK language. `useSiteLocale()` supplies `locale`, the existing manual preference, `setLocale()`, `href(path)` for internal links, and `basePath` for route comparisons. English uses unprefixed URLs, Slovak `/sk`. Stable app/QR/auth/share endpoints keep their paths and receive `lang`. Marketing URLs determine content language; discovery retains its automatic gym/browser default when no explicit preference exists. Only manual choices write the one-year `liftag-language` cookie.

Legacy query redirects run in `server/plugins/site-locale.ts` before Nitro 2’s public request handler, because its static middleware runs before scanned server middleware. The corresponding query conditions in `new_app/vercel.json` run at the Vercel edge before static/ISR delivery. Redirect responses do not cache or save a preference. Anchors remain in client navigation and survive HTTP redirects through browser fragment inheritance.

Nuxt generates twins of a single page. Do not create new `pages/sk` templates. Existing Czech legal routes remain independent. Use `siteBasePath` for route checks and `siteLocalePath` in pure code. Keep all query/identity/filter parameters and hashes when switching. Do not rewrite external, asset, API, mailto, or tel URLs.

## Component messages

Each feature owns `new_app/i18n/messages/<feature>.ts`. Export `en` and `sk`; require `sk satisfies typeof en` (or `LocalizedContent<typeof en>` for literal types). Namespace keys by feature; do not use English sentences or numeric extraction IDs as keys. Components import their own messages and use:

```ts
import { en, sk } from '~/i18n/messages/example'
const { t, n, d } = useI18n({ useScope: 'local', messages: { en, sk } })
const { href, locale } = useSiteLocale()
const label = computed(() => t('example.label'))
```

Template: `{{ t('example.label') }}` and `:to="href('/pricing')"`. Local composers inherit the root locale. Do not change their locale or create another cookie. Shared common strings use the global composer. Keep state/IDs/form values separate from translated labels. `t()` uses `{name}` parameters (not double braces). Translate a whole sentence. Use `<i18n-t>` named slots for inline links/emphasis; trusted existing HTML copy can remain `v-html` where it was already used.

Pure/server renderers can call `createMessageTranslator(locale, { en, sk })` with their flat feature messages. This is Vue I18n with the same Slovak plural rules, independent of a Nuxt component or request cookie. Keep translators scoped to the calling operation. Escape literal pipes in UI/SEO messages as `{'|'}` using Vue I18n literal interpolation; bare `|` separates plural forms.

For arrays, `tm` returns compiled message values; resolve leaves with `rt`. Structured long-form content can be typed EN/SK data selected reactively and imported only by its owning route. Do not stringify user data into HTML. Do not copy page templates for each language. `useLiftagSeo` and `useLiftagStructuredData` accept getters; pass a getter when values depend on locale.

The global Slovak plural forms are `one | few | many (fractions) | other`. Three forms support `one | few | other` for integer counts. Use `Intl`/i18n number and date formatting without changing underlying values, units, or calculator math.

Exercise overlays remain English in `content/exercises/<slug>.ts`; complete Slovak counterparts go in `content/exercises/sk/<slug>.ts` with the same `ExerciseOverlay` type and identities. The async loader imports only the selected guide. Do not invent or translate slug values, relatedSlugs, IDs, URLs, measurements, factual claims, or names of brands/people/gyms. Preserve optional fields and array order.

## Slovak writing

Natural Slovak takes precedence over word-for-word English. Consumer copy uses direct singular address; business copy stays professional, legal wording faithful. Keep sentences short without omitting meaning. Use correct diacritics and grammatical cases. Terminology: workout = tréning; exercise = cvik; set = séria; reps = opakovania; personal record/PR = osobný rekord; workout tracking = zaznamenávanie tréningov; progress = pokrok; routine = tréningová zostava (or simply tréning where clear); plan = tréningový plán; workout logger = tréningový denník; dashboard = prehľad or správa according to context; gym = fitko in casual consumer UI, fitness centrum when the business/legal context calls for it. Prefer "zaznamenať sériu" over "logovať set". Rephrase around external names when their grammatical case cannot be inferred. Preserve standard technical names NFC, QR, RPE, 1RM and product/brand names. Established English gym terms (bench press, hip thrust, superset, etc.) are welcome when they sound natural in Slovak; do not force awkward substitutes. Translate sentence grammar and meaning, never replace individual English words mechanically.

Translate all visible text, aria/alt/title/placeholder text, empty/error/loading states, dynamic chart/canvas labels and metadata. Existing screenshots, recordings, logos and static artwork stay unchanged. Backend content stays API-owned: request its locale and honor provided fallback. Video selection is requested locale → English → available, with displayOrder inside a locale. Shared HLS audio language must update even if the source URL remains identical.

## Agent ownership and verification

Only explicitly configured `gpt-5.6-luna` subagents, at most three at once. Never substitute another model. Each owns its assigned paths and uniquely named message files. Coordinator owns shared route/locale/SEO infrastructure, app/config, dependencies and lockfile, and final integration. Do not revert another agent's edits or commit/push on your own. Report coverage and remaining gaps.

Use `./node_modules/.bin/nuxt typecheck` from `new_app` during work (the host's root pnpm shim tries a different pnpm version). Use Node's existing tests for meaningful behavior. Do not add implementation-mirroring tests for individual translated labels. The coordinator runs the final production SSR and browser suites after integration. Do not submit real contact forms or alter backend/app/dashboard repositories.


## Acceptance checks

`VERCEL_ENV=preview pnpm verify` runs unit checks (including message/guide coverage), typechecking and the default deployment build. Also build with `NITRO_PRESET=node-server` and `NITRO_PRESET=vercel`.

For reproducible API and browser checks, start `node --experimental-strip-types tests/fixtures/discovery-server.mjs` from `new_app`, then run the app with `NUXT_PUBLIC_API_BASE_URL=http://127.0.0.1:4015` on port 3002. Run `node --experimental-strip-types tests/discovery.integration.mjs`, `node tests/siteLocale.integration.mjs`, and `pnpm test:browser` against that server (`DISCOVERY_TEST_ORIGIN` overrides its URL). Install engines once with `pnpm exec playwright install chromium webkit`. The browser suite uses isolated contexts for Chromium/WebKit desktop and mobile, never existing account sessions. Turnstile rejects localhost; tests do not submit forms.

Synthetic catalog video URLs test metadata selection and missing-media behavior; native/HLS.js audio selection and listener cleanup have focused unit coverage. Availability and playback of deployed localized backend media remain a separate production check because live API calls currently return 403.
